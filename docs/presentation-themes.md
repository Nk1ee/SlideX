# Визуальные темы презентации

Тема выбирается отдельно от содержания, storyline и количества слайдов. В wire contract она передаётся в существующем поле style; отдельное поле и второй источник правды не создаются.

## Доступные варианты

| Идентификатор | Стиль | Палитра | Назначение |
|---|---|---|---|
| deep_blue | Деловой | Глубокий синий | Текущий вариант и совместимый выбор по умолчанию для существующего FSM |
| business_slate | Деловой | Светлый сланец | Светлая строгая подача |
| business_emerald | Деловой | Тёмный изумруд | Сдержанная тёмная альтернатива |
| minimal_light | Минималистичный | Светлый | Спокойная светлая подача с тонкими акцентами |
| minimal_graphite | Минималистичный | Графитовый | Спокойная тёмная подача с тонкими акцентами |
| minimal_sand | Минималистичный | Тёплый песок | Тёплая светлая подача для гуманитарных тем |
| dynamic_violet | Динамичный | Фиолетовый импульс | Контрастная тёмная подача с сильными акцентами |
| dynamic_coral | Динамичный | Коралловый импульс | Тёплая контрастная подача |

Пользовательские названия, описания, семейства и токены рендеринга находятся в src/presentation/themes.ts. Допустимые идентификаторы определяются только themeIdSchema в src/presentation/schema.ts.

## Интеграция с ботом

Текущий FSM может продолжать передавать deep_blue, поэтому существующий поток не требует немедленного изменения. Когда в боте появится выбор, он должен:

1. показать варианты из каталога;
2. сохранить выбранный стабильный идентификатор в FSM;
3. передать его как presentationRequest.style;
4. сохранить это значение без исправлений в metadata презентации.

Неизвестный идентификатор отклоняется контрактом. Автоматической подмены на другую тему нет.

## Расширение

Новый вариант добавляется одновременно в themeIdSchema и исчерпывающий каталог. Рендерер получает палитру и геометрию выбранной темы из каталога. Семейства различаются цветами, толщиной титульного акцента и разделителей. На титульных слайдах деловых и динамичных тем используются диагональные мотивы справа от текста; минималистичные темы оставляют это пространство свободным. На прочих layouts диагональный мотив пока не применяется: каждому из них нужна отдельная проверка композиции.

Палитра не меняет учебный контент, метаданные, количество слайдов или правила layout. Новая тема становится доступной пользователю только после поддержки рендерером и визуальной проверки.

## Основа дизайна

Первый сравнительный макет из обсуждения принят как ориентир для восьми первых тем. Реальный PPTX создаётся кодом и может отличаться в шрифтах и точной геометрии от иллюстративного изображения. Поэтому бот должен показывать превью, полученные из актуального рендерера, после проверки на целевых устройствах.

- [Исходный макет с семью темами](themes/original-seven-reference.png) — выбранное пользователем направление.
- [Сравнение восьми тем из реальных PPTX](themes/first-eight-rendered.png) — актуальная визуальная проверка титульных слайдов.
- [Векторный лист восьми тем](themes/first-eight.svg) — воспроизводимая схема для дизайнерских правок.

Воспроизведение: `npm run build`, затем `node scripts/generate-theme-board.mjs` и `node scripts/generate-theme-samples.mjs`. PPTX-образцы сохраняются в `work/theme-samples/`. Для проверки в установленном PowerPoint: `scripts/render-pptx-windows.ps1` для каждого PPTX, затем `scripts/compose-theme-board.ps1`.
