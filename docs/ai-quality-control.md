# AI-контроль изображений и слайдов

AI-контроль дополняет точные программные проверки, но не заменяет их. Программа надёжнее проверяет количество слайдов, metadata, обязательные поля, размеры файлов и структуру PPTX. Vision-модель полезна там, где требуется смысловая оценка изображения или визуальной композиции.

## Порядок проверок изображения

1. Gemini создаёт `visual` plan: `type`, `concept`, `query_en`, `placement`.
2. Provider ищет кандидатов по `query_en`, а не по общей теме презентации.
3. Детерминированные проверки отсеивают generic stock, нерелевантный текст, неизвестный источник, неверную лицензию, MIME, размер и разрешение.
4. AI получает только контекст конкретного слайда и проверенные байты лучшего кандидата.
5. Ответ AI проходит строгую Zod-схему.
6. `accept` разрешает картинку. `reject` и `review` заставляют resolver попробовать следующего кандидата. Ошибка API и неверный JSON останавливают AI-проверку данного слайда: повторять запрос для следующих изображений при сбое сервиса бессмысленно.
7. Если хороших кандидатов нет, resolver возвращает `null`; renderer или orchestration выбирает layout без изображения.

AI не меняет слайд, не создаёт текст и не исправляет user metadata. В решение входят смысловая релевантность, учебная ценность, generic stock, читаемость текста внутри изображения и краткое наблюдаемое основание. `textEssential` отличает важные подписи диаграммы от случайных надписей на фоне фотографии. Нечитаемый существенный текст блокирует принятие; случайный текст сам по себе не блокирует релевантную фотографию. Инструкции, напечатанные внутри изображения, считаются недоверенными данными.

## Контракт

`src/qc/visualAi.ts` содержит два независимых отчёта:

- `ImageAiQualityReport` — проверка изображения до PPTX;
- `SlideAiQualityReport` — проверка PNG готового слайда после render.

Три решения имеют точный смысл:

- `accept` — проверка разрешает дальнейший шаг;
- `reject` — найден конкретный дефект;
- `review` — модель не уверена; production pipeline трактует это как отказ от автоматического использования.

Zod проверяет не только поля, но и противоречия: нельзя принять нерелевантное, misleading или generic-stock изображение; нельзя принять слайд с failed check или error.

## Gemini adapter

`src/qc/geminiVisualEvaluator.ts` отправляет JPEG/PNG inline в Gemini `generateContent` и просит structured JSON через совместимые с `v1beta` поля `generationConfig.responseMimeType` и `responseSchema`. Ответ затем проверяется локальной Zod-схемой. Настройки приходят извне:

```env
GEMINI_API_KEY=
GEMINI_QC_MODEL=
```

Имя модели специально не зашито в код. Ключ не попадает в URL, логи или отчёт об ошибке. В запрос изображения не передаются имя студента, группа и другие user metadata.

### Живая проверка 2026-09-23

Для ключа проекта `gemini-3.1-flash-lite` успешно обработала три контролируемых случая: [схема нейронной сети](https://commons.wikimedia.org/wiki/File:Multi-Layer_Neural_Network-Vector.svg) принята для слайда о слоях сети; [фотография библиотеки](https://commons.wikimedia.org/wiki/File:Bookshelves_and_interior_of_the_library_of_the_Academy_for_Judiciary.jpg) принята для слайда о библиотечном пространстве; та же схема сети отклонена для слайда о реформах Петра I. Мелкие надписи на корешках книг признаны случайным текстом, а подписи узлов схемы — существенным. Все ответы прошли локальную Zod-проверку. Полный обезличенный отчёт хранится только в игнорируемой папке `work/`.

Это smoke test из трёх примеров, а не измерение точности на большом наборе. Доступность модели может меняться: `gemini-3.8-flash` и `gemini-3.6-flash` в этой сессии возвращали HTTP 503, а `gemini-2.5-flash` присутствовала в списке Models API, но при генерации отвечала HTTP 404 для нового пользователя. Production-модель надо проверять реальным вызовом и задавать через `GEMINI_QC_MODEL`.

## Проверка готового слайда

Следующий этап использует PNG, отрендеренный из PPTX, и соответствующий canonical slide JSON. Vision-модель проверяет читаемость, overlap, clipping, контраст, иерархию, соответствие изображения, а также отдельные требования `sources` и `conclusion`.

Это не является проверкой фактов. Фактические утверждения, цитаты, статистика и источники требуют отдельного provenance/grounding gate. AI-отчёт о слайде сначала используется в regression и ручном контроле. Делать его production-блокером следует только после измерения ложных отказов на canonical наборах.

## Маршрутизация исправлений

| Проблема | Ответственный шаг |
|---|---|
| Нерелевантная картинка | resolver пробует следующего кандидата |
| Нет хорошей картинки | layout без изображения |
| Overflow текста | semantic repair через Gemini без изменения metadata |
| Overlap или clipping | исправление renderer/layout |
| Сомнительный факт | проверка источника, а не visual evaluator |
| AI не уверен | `review`, автоматическое использование запрещено |

Для контроля стоимости AI проверяет не более трёх лучших кандидатов после дешёвых фильтров; лимит настраивается через `maxAiCandidatesPerSlide` (1–10). Повторные вызовы и cache добавляются после измерения реальной нагрузки.
