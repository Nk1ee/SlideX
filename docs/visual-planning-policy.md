# Semantic visual planning policy

Цель: выбирать фотографию, иллюстрацию, схему, диаграмму, timeline или отсутствие визуала по смыслу слайда и учебному контексту. Политика не создаёт контент и не заставляет заполнять каждый слайд изображением.

## Какие данные нужны от FSM

Текущий FSM передаёт тему, предмет, имя, группу, число слайдов и стиль. Этого недостаточно, чтобы надёжно определить возраст. Значение `group` нельзя использовать как класс: `4` может означать четвёртый класс, курс или номер группы.

Для полноценного подключения политики бот должен передавать trusted learning context:

- `educationStage`: `school`, `college`, `university`;
- `schoolClass`: свободная строка только для школы, например `8Г`; исходное значение сохраняется;
- `course`: свободная строка для колледжа или вуза; группа остаётся в trusted поле `group`;
- `task`: `explain_topic`, `class_report`, `project_defense`, `research_report` или `biography`.

Первая ветка диалога уже согласована: «Где вы учитесь?» → школа/колледж/вуз. Школа запрашивает класс; колледж и вуз — курс и группу. Пока production Telegram FSM не обновлён, старые запросы используют `unknown`, и код не угадывает возраст.

## Порядок принятия решения

1. Сначала определяется задача конкретного слайда: реальный объект, механизм, процесс, сравнение, доказательство числами, хронология, цитата, вывод или источники.
2. Затем проверяется наличие данных. Chart разрешён только при переданных числах и источнике. Chronology требует переданных дат. Diagram требует отношений или процесса, которые нужно объяснить.
3. Предмет задаёт приоритет, но не отменяет смысл слайда.
4. Возраст влияет на сложность и способ подачи, но не заставляет добавлять нерелевантную картинку.
5. Количество слайдов задаёт визуальный бюджет и ритм. Это потолок и ориентир, а не обязательная квота.

## Базовые правила

| Условие | Предпочтительный формат |
|---|---|
| Проверяемые числовые данные | chart |
| Хронологическая последовательность | timeline |
| Механизм, процесс, устройство, связи | diagram |
| Реальная персона, место, объект | photo |
| Абстрактное введение для 1–4 класса | illustration |
| Цитата, conclusion, sources | none |
| Нет визуала, который помогает понять материал | none |

Для истории полезны документальные изображения, карты и timeline. Для биологии, физики, химии и информатики приоритет имеют объясняющие схемы. Для математики диаграмма допустима только для реальных числовых данных; формула или геометрическая схема не должна подменяться stock-фотографией. Для литературы фотография уместна для автора, места или эпохи, но не как украшение каждого тезиса.

## Возраст

- 1–4 класс: одна мысль на слайд, конкретная иллюстрация, простая схема, минимум подписей.
- 5–8 класс: баланс фотографий и объясняющих схем, простые диаграммы с прямыми подписями.
- 9–11 класс: больше доказательств, источников, сравнений и числовых диаграмм.
- Колледж/вуз: технические схемы и sourced charts допустимы при достаточной читаемости и предметной необходимости.

## Количество слайдов

`visualBudgetFor` исключает title и последние служебные слайды, затем рассчитывает целевое и максимальное число насыщенных визуальных слайдов. Один формат нельзя повторять более двух раз подряд. Если релевантного изображения нет, бюджет не заполняется плохой картинкой: `NO IMAGE > BAD IMAGE`.

## Граница ответственности

Gemini определяет `slidePurpose`, visual concept и поисковый запрос. TypeScript policy даёт формат и ограничения. Validator проверяет данные, источник, повторения и бюджет. Renderer только создаёт композицию. Image provider ищет уже запланированный visual и может вернуть `null`.
