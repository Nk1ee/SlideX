# Изображения в SlideX

Путь одного слайда: `visual.concept` + `visual.query_en` → поиск → проверка происхождения и лицензии → проверка смысловой связи → dedupe → скачивание и проверка байтов → `image_text` в PPTX. Общая тема презентации не подставляется вместо visual-плана слайда.

- `providers.ts` обращается к Wikimedia Commons или Unsplash. Wikimedia принимает файлы с лицензией CC0, Public domain или CC BY с данными автора и умеет брать проверяемое PNG-превью SVG-схем; Unsplash требует access key, имя фотографа, ссылку на профиль и download tracking URL. Результат без нужных данных отбрасывается.
- `relevance.ts` отсекает очевидные generic stock описания и требует пересечения слов запроса и описания. Это консервативный текстовый фильтр, а не доказательство того, что картинка действительно подходит по смыслу.
- `resolve.ts` сохраняет порядок провайдеров как приоритет: сначала выбирает лучший пригодный результат первого провайдера и только затем переходит к fallback. При ошибке пробует следующий кандидат; provider ID и одинаковые байты не повторяются в пределах презентации. Отсутствие хорошего результата возвращается как `null`.
- `download.ts` скачивает только с разрешённых доменов по HTTPS, не следует редиректам, ограничивает файл 8 MiB, проверяет MIME, сигнатуру и минимальные размеры JPEG/PNG. Для Unsplash после успешной загрузки вызывает download tracking endpoint.
- `pptx.ts` добавляет видимую подпись автора и лицензии со ссылкой. Полные сведения, адрес источника, ссылка на лицензию и способ размещения помещаются в заметки слайда. Фотографии кадрируются, а диаграммы вписываются полностью на контрастной подложке. Длинный CC0/Public domain credit сокращается на самом слайде до названия Wikimedia, а полный текст остаётся в заметках.

Секреты берутся только из окружения. `npm run sample:image` использует только Wikimedia и не требует ключа. Unsplash и Wikimedia проверены живыми запросами с локальным `UNSPLASH_ACCESS_KEY`; ключ не сохраняется в PPTX или Git. Перед production-включением всё равно нужна повторная проверка актуальных правил API. Сетевые ошибки и плохие результаты не превращаются в произвольную картинку.

Сейчас нет автоматического переключения `image_text` в другой layout: при отсутствии изображения renderer возвращает ошибку, а orchestration должен запросить или выбрать другой layout с уже имеющимся содержимым. `npm run sample:gallery` создаёт семислайдовый пример для визуального QA. ZIP-тесты не выявляют все перекрытия и не оценивают качество кадрирования, поэтому sample нужно рендерить и просматривать после изменений.

Проверенные первичные документы провайдеров: [Unsplash API](https://unsplash.com/documentation), [Unsplash API Terms](https://unsplash.com/api-terms), [MediaWiki Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo) и [правила повторного использования Wikimedia Commons](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia). Перед production-запуском нужно повторно сверить актуальные условия Unsplash, в частности требования к показу, ссылкам и учёту скачиваний.
