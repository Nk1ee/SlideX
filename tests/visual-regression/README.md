# Визуальная регрессия SlideX

Это **синтетические тестовые образцы**, не готовый учебный материал. Пять корректных слайдов созданы локальным renderer SlideX; два дефектных PPTX созданы отдельным тестовым кодом. Источники в примере относятся к реальным внутренним документам проекта и не выдаются за внешнюю академическую литературу.

Каждый случай в `manifest.json` связывает canonical slide JSON, PPTX, номер слайда в PPTX, PNG 1600×900 и ожидаемое решение. PPTX/PNG намеренно сохранены в Git: тест можно повторить и посмотреть без Gemini API и без установленного PowerPoint. Обычный `npm run check` проверяет целостность всего набора, но не утверждает, что пиксели выглядят хорошо.

Обновление образцов после осознанного изменения renderer:

1. `npm run sample:visual-regression` — пересоздать JSON и PPTX.
2. В Windows с установленным PowerPoint: `scripts/render-pptx-windows.ps1 -PptxPath tests/visual-regression/assets/good.pptx -OutputDirectory work/visual-regression-good` и аналогично два дефектных PPTX. Скопировать `slide-N.png` под имена из `manifest.json`.
3. Просмотреть **все** PNG вручную, особенно `sources` и `conclusion`, затем выполнить `npm run check`.
4. При наличии `GEMINI_API_KEY` и `GEMINI_QC_MODEL` выполнить `npm run review:regression`; отчёт появится в игнорируемом `work/visual-regression-report.json`. Пакетная команда делает до двух повторов только при временных ответах 429/5xx. Успешные ответы кэшируются по модели и SHA-256 PNG, поэтому следующий запуск продолжает прерванную проверку без повторной оплаты уже проверенных файлов.

AI-оценка пока диагностическая. `accept` на дефектном примере — ложное принятие; `reject` на хорошем — ложный отказ; `review` означает неопределённость. Совпадение на семи примерах не доказывает надёжность модели в production. Нужны дополнительные реальные презентации, варианты тем, изображений и менее очевидных дефектов.
